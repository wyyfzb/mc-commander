# MC_Commander 用户向导

MC_Commander 是一个自托管的 Minecraft 服务器管理面板：**无需安装任何插件、无需进入游戏**，在浏览器里完成玩家管理与服务器运维。本向导带你从零走通核心流程（约 10 分钟）。

> 文中截图为示例数据（虚构环境），实际面板显示你服务器的真实状态。

## 1. 部署面板

**操作路径**：参考仓库 README「快速开始 → 服务端部署」。

| 方式 | 适用 |
|------|------|
| **Linux 一键部署（推荐）** | Ubuntu/Debian 服务器，脚本自动安装 Node.js、Java 并拉起面板 |
| 手动部署 | 其他系统或已有环境；需自行构建前端产物并放入服务端 `public/`（见 README「方式二：手动部署」）。只跑后端 API 时可 `npm ci && npm start`——此时浏览器访问 25566 拿不到面板界面 |

**预期结果**：面板服务监听 25566 端口，浏览器访问 `http://<服务器地址>:25566` 出现登录页（见第 2 步）。

> 平台支持：Linux 全支持；Windows 与 macOS 为实验性（官方部署脚本与发布包面向 Linux，需按 README「手动部署」自行构建前端产物，Windows 建议 WSL2；macOS 系统自带 rsync 的硬链接去重未验证，备份会自动探测降级，建议以 `RSYNC_BIN` 指向 GNU rsync）。

## 2. 首次设密

首次访问面板会进入**设置管理员密码**向导（onboarding）。

**操作路径**：浏览器打开面板地址 → 按向导设置管理员密码（需同时确认两次）→ 如服务端配置了部署令牌（SETUP_TOKEN），按提示输入。

**预期结果**：设密成功后自动登录进入仪表盘。此后每次访问只需输入管理员密码（会话有效期 7 天，可滑动续期；可在「设置 → 账号与安全」中下线或踢出其他设备）。

## 3. 创建 MC 实例

**操作路径**：侧栏「实例」→ 页面右上「新建实例」。

**方式一：面板一键部署（推荐）**
选择 MC 版本（自动匹配对应 Java 版本）→ 设置实例名称与内存分配 → 确认创建。面板自动下载服务端 JAR 并初始化。
部署期间进度条实时显示下载/安装/首启阶段；如需中止，点进度视图里的「取消部署」并确认——
面板会终止下载或安装进程并清理未完成的实例目录，不会在实例列表里留下半个实例
（若目录仍被正在退出的进程占用而删除失败，弹窗会明确说明收尾未完成）。

**方式二：手动创建**
填入已有服务端目录路径（含 `server.jar`）→ 面板读取并接管。

**预期结果**：实例出现在实例列表，显示名称与状态（已停止）。

## 4. 启动与连接

**操作路径**：实例卡片 → 点「启动」。

**预期结果**：
- 实例状态变更为「运行中」，卡片显示在线人数与 TPS；
- 玩家在游戏内通过 `<服务器地址>:25565` 连接（地址见仪表盘顶栏）；
- 首次启动如遇 EULA 未同意，面板会弹出协议确认对话框，同意后自动写入并重启。

## 5. 日常管理

### 仪表盘（终端与命令）

**操作路径**：侧栏「仪表盘」。

- **服务器终端**：实时日志输出，可直接输入命令发送（如 `say hello`），无需 RCON 客户端；
- **性能概览**：CPU / 内存 / TPS 曲线，世界昼夜时钟与天气控制（需 RCON 已启用）；
- **命令面板**：`Ctrl/⌘+K` 快速跳转页面或执行预设命令（macOS 用 ⌘，其他平台用 Ctrl）。

### 玩家管理

**操作路径**：侧栏「玩家」。

- **实时列表**：在线/离线玩家、模式、维度、坐标、延迟；
- **图形化操作**：传送、给予物品（含附魔/药水/自定义 NBT）、封禁/解封、白名单、OP、踢出、清空背包——全部由面板自动生成命令，无需手敲 MC 命令；
- **筛选与搜索**：按状态/模式/维度过滤，支持批量操作（如批量给予、批量踢出）。

![玩家管理](../screenshots/players.png)

### 文件管理

**操作路径**：侧栏「文件」。

- 浏览服务器目录（配置文件、世界文件、插件目录等）；
- 双击文本文件在浏览器内编辑（内置编辑器，`Ctrl/⌘+S` 保存），如调整 `server.properties`、`ops.json`；
- 上传/下载/重命名/新建，删除高危目录有红色确认提示。

![文件管理](../screenshots/files.png)

### 备份

**操作路径**：侧栏「设置 → 备份管理」。

- **创建备份**：快照式备份（默认保留最近 10 份、30 天，均可通过服务端环境变量配置）；
- **恢复备份**：从列表选择备份一键恢复（恢复前自动二次确认）；
- **下载**：备份可下载到本机做离机容灾；
- **归档快照**：卸载实例时会保留它的快照目录（磁盘上的事实副本），但备份列表里不再显示，
  未挂载的会随保留期被自动清理。列表下方出现「归档快照（未建立索引）」时，可把其中仍可用的
  快照**挂载**到当前实例——挂载只登记索引，不复制、不移动磁盘内容，挂载后即可正常恢复/下载/
  删除。挂载后的条目就是当前实例的普通备份：计入当前实例的备份配额，超出保留策略
  （数量/天数）时按创建时间最旧优先被自动清理（挂载行按挂载时刻计时），删除条目会一并删除
  磁盘上的原归档快照（挂载不复制，它是唯一副本）。
  **卸载前若还想保留这些备份，请先下载到本机或挂载给另一个实例。**

![备份](../screenshots/backup.png)

### 离机副本（外部拉取）

面板的备份默认与实例数据**同盘**——磁盘或主机损毁时**两者一起没**。真正的容灾需要把
副本放到**本机之外**，做法是让外部机器定期从面板**拉取**备份（`GET /backups/:id/download`
是流式 tar.gz，走既有鉴权），而不是让面板往外推。

**适用形态**：局域网内的另一台机器或 NAS（单机自托管的常见形态）。
仓库另附可直接使用的示例脚本 [scripts/pull-backups.sh](../scripts/pull-backups.sh)。

**要留意的两点**：

1. **威胁模型会变**。备份是**明文、未加密、未签名**的完整副本（含世界数据），面板的
   安全假设是「**目录权限即数据边界**」（见 `SECURITY.md`）。副本一旦离开本机，这条边界
   就不再成立——目标机器上的任何可读者都能看到世界数据。请据此限制目标机权限，
   必要时自行加密后再落地。
2. **面板自身也要一起覆盖**。面板的 SQLite 库与 `.env` 伴生副本有**独立一套保留**
   （落 `backups/panel/`，不入实例备份列表）。只拉实例备份的话，主机损毁后**面板配置
   与管理凭据无法重建**。

**恢复语义**：远端副本须**先拉回本地同一个盘**（与 `backupsDir` 同一文件系统）才能进
既有恢复链——快照链靠硬链接去重，跨设备会退化成全量复制。

> **凭据**：该端点要求**管理员**凭据（只读凭据会 403），脚本用 `X-API-Key` 或
> 会话 Bearer 均可。**不要把凭据写进脚本或提交进仓库**，用环境变量传入。

### 审计日志

**操作路径**：侧栏「审计日志」。

- 操作审计：登录、实例启停、玩家操作、配置修改等全部留痕（含来源与详情）；
- 命令历史：所有经面板/终端执行的命令、来源、执行结果与耗时；
- 支持按操作类型与时间范围过滤。

## 6. 常见问题

| 现象 | 处理 |
|------|------|
| 面板提示「需启用 RCON」 | 在 `server.properties` 中设置 `enable-rcon=true` 并配置密码，重启实例 |
| 命令已发送但看不到响应 | RCON 未启用时命令照常下发但响应不可见（页面有提示横幅） |
| WebSocket 连接上限 | 面板最多同时接受 32 个 WebSocket 连接，超出的新连接被拒绝；实例数据默认每 30 秒自动刷新（WebSocket 在线时叠加实时推送） |
| 忘记管理员密码 | 密码只存哈希、无法反解；清空管理员账号与会话后重启即可回到首访设密流程（命令与注意事项见服务端 README「忘记管理员密码」） |
