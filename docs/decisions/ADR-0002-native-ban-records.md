# ADR-0002：封禁等功能服务端自实现

- 状态：accepted
- 日期：2026-08-07

## 背景

原版 Minecraft 只有永久 `/ban`，没有临时封禁；禁言（mute）在无插件前提下
无任何实现途径。走插件路线（EssentialsX 等）与「无插件」架构冲突。

## 决策

- **临时封禁**：服务端自建 `temp_bans` 表（目标玩家/IP、时长、理由、到期时间），
  TaskScheduler 每分钟轮询，到期自动执行 pardon / pardon-ip；前端封禁弹窗
  提供 6 档时长 + 9 个预设理由，玩家列表显示剩余时长徽章
- **禁言**：判定为原版不可能实现，**移除该功能**（不做伪实现）
- **治疗 / 喂饱 / 主城**：用原版 `effect` / `tp` 命令组合自实现
- **文件同步**：banned-players/banned-ips/whitelist/ops.json 在面板内编辑时，
  校验合法 JSON 后以串行同步命令落盘（原版 MC 运行中不重读这些文件）；
  ops.json 的 level 精确值无法用命令表达（原版 op 固定 level 4），接受此限制

## 后果

- 封禁功能的真相来源 = 服务端接口 + temp_bans 表，而非 MC 本体状态
- 上界清晰：凡原版命令空间覆盖不了且文件写不进去的能力，明确不做
